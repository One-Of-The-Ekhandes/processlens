# ProcessLens

[![CI](https://github.com/One-Of-The-Ekhandes/processlens/actions/workflows/ci.yml/badge.svg)](https://github.com/One-Of-The-Ekhandes/processlens/actions/workflows/ci.yml)

ProcessLens is a small Linux user-space tool built to better understand how running processes
are represented by the operating system.

Instead of relying on abstractions, it reads directly from the `/proc` filesystem and exposes
a few core signals about a process in a simple, inspectable way.

This project is intentionally minimal and focused.

---

## What it does

For a given process ID (PID), ProcessLens reads:

- the current process state  
- resident memory usage (VmRSS)  
- number of threads  

All data is obtained from kernel-exposed files under `/proc`.

It also supports listing the top *N* processes by memory usage to observe system-level behavior.

---

## Why this project exists

The goal of ProcessLens is not to replace existing tools like `top` or `ps`.

It exists to:
- understand how Linux exposes process information
- practice reading and interpreting `/proc` safely
- work with real system data instead of simulated inputs
- build something small that is easy to reason about and explain

---

## Build

```bash
make            # gcc -O2 -Wall -Wextra -std=c11
```

## Usage

```bash
./processlens 1          # one process by PID
./processlens --top 5    # five processes using the most resident memory
```

Example:

```text
$ ./processlens 1
PID:     1
Name:    systemd
State:   S (sleeping)
VmRSS:   12544 kB
Threads: 1
```

Exit codes: `0` success, `1` process not found or not readable, `2` invalid arguments.

## How it works

Linux exposes every running process as a directory under `/proc`. The file `/proc/<pid>/status` is plain text generated by the kernel each time it is read, with lines such as `State:`, `VmRSS:` and `Threads:`.

- `processlens <pid>` opens that file and parses those lines.
- `processlens --top <n>` lists `/proc`, keeps the numeric directory names (one per process), reads each status file, sorts by `VmRSS` and prints the top `n`. A process can exit between listing and reading; it is simply skipped.

Notes:

- `VmRSS` is the resident set size: memory currently held in RAM, in kilobytes.
- Kernel threads have no user memory, so they have no `VmRSS` line and show 0.
- Reading another user's processes may need extra permissions on hardened systems.
